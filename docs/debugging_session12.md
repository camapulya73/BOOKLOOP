# Занятие 12 — отладка BOOKLOOP

## Установка и запуск инструментов

```bash
python -m pip install -r requirements.txt
python manage.py check
python manage.py runserver
```

Django Debug Toolbar автоматически подключается только при `DEBUG=True` и установленном `django-debug-toolbar`. Откройте любую страницу с HTML-ответом; панель должна появиться справа. Маршрут панели: `/__debug__/`. `INTERNAL_IPS` настроен для `127.0.0.1` и `::1`.

Файловый журнал создаётся автоматически: `logs/app.log`. Формат каждой записи: дата/время, уровень, logger/module, сообщение. Уровни INFO и выше записываются в файл. Не коммитьте содержимое логов: `logs/*.log` добавлен в `.gitignore`.

## Отладчик Python в VS Code

1. Установите расширение Python от Microsoft.
2. Откройте `books/views.py`, поставьте breakpoint внутри `search_books_json` или `toggle_favorite`.
3. Выберите Run and Debug → Django (если конфигурации нет, создайте `.vscode/launch.json` с `django`/`manage.py runserver`).
4. Выполните соответствующее действие в браузере.
5. В панели Variables проверьте `request.GET`, `q`, `qs`, `copy`; в Call Stack просмотрите стек вызовов; используйте Step Over/Into.

Альтернатива для терминала: временно поставить `breakpoint()` в нужном месте и запустить сервер в том же терминале. Удалите breakpoint перед коммитом.

## Сценарии пяти классов дефектов для контролируемой проверки

Не добавляйте неисправный код в рабочую ветку. Воспроизводите сценарии на тестовых данных и проверяйте защиту:

1. **Логика расчёта:** проверить агрегат `profile_obj.copies.aggregate(total=Count('id'))`; сравнить total с числом экземпляров в БД. Точка останова — `books/views.py`, `profile`.
2. **Отсутствующий объект:** открыть `/books/999999/`. Ожидаемое поведение — контролируемый 404 через `get_object_or_404`, а не AttributeError. Проверить Network и traceback/log.
3. **Неверный тип:** отправить в фильтр поиска произвольную строку, например `?q=123abc`; запрос должен обработаться как строка без арифметических преобразований. Проверить `request.GET` и SQL panel.
4. **Шаблон/контекст:** открыть каталог без результатов поиска. Проверить, что пустое состояние отображается, а шаблон не обращается к отсутствующему ключу контекста.
5. **JavaScript:** в DevTools → Sources поставить breakpoint в `runSearch` перед `fetch`, ввести поисковый запрос; проверить `searchUrl`, `params`, `response.status` и `data`. В Network изучить GET `/api/books/search/?q=...`.

Для каждого случая заполните журнал наблюдений фактическими симптомами, гипотезами, проверкой, причиной и коммитом. Если дефект не обнаружен, фиксируйте это как проверенный отрицательный сценарий, а не как «исправленный дефект».

## Проверка N+1

В каталоге и карточках уже используются `select_related('book', 'owner__reader')` и `prefetch_related('photos', 'book__genres')`. Откройте каталог с Debug Toolbar → SQL, запишите число запросов. Затем временно (только локально, не коммитя) сравните вариант без этих оптимизаций, обновите страницу и сравните число запросов. Верните оптимизированный вариант. Зафиксируйте одинаковые условия и скриншоты обеих версий. Если данных мало, создайте несколько тестовых экземпляров.

## Проверка fetch и регрессия

- Network: введите запрос в живой поиск. Зафиксируйте GET, URL `/api/books/search/`, статус, Request Headers, Query String Parameters, Response и Timing.
- Избранное: откройте карточку, нажмите кнопку. Зафиксируйте POST, статус и JSON-ответ.
- Sources: breakpoint в `books/static/books/app.js` внутри `runSearch` или обработчика формы избранного; снимок Variables/Scope.
- После изменений проверьте главную, каталог, карточку, регистрацию, вход, добавление книги, профиль, избранное и обмены.

## Важное замечание

Панель Debug Toolbar и интерактивный debugger доступны только при локальном запуске. Скриншоты, фактическое число SQL-запросов, HTTP-статусы и хеши коммитов фиксируются разработчиком на его машине; они не генерируются автоматически этим проектом.
